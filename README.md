# PMLDL Assignment 1: Deployment

Automated MLOps pipeline that predicts the winner of an ATP tennis match.

## Task

Binary classification: given two players (ATP ranks and points) and the match
conditions (surface, court, tournament series, round, best-of format), predict
whether Player 1 wins.

- **Dataset:** [ATP Tennis 2000-2023](https://www.kaggle.com/datasets/dissfya/atp-tennis-2000-2023daily-pull), filtered to matches from 2015 onwards
- **Model:** RandomForestClassifier — test accuracy 0.63, ROC-AUC 0.69

## Pipeline

| Stage | Tool | Code | Output |
|---|---|---|---|
| 1. Data engineering | DVC | `code/datasets/prepare_data.py` | `data/processed/train.csv`, `test.csv` |
| 2. Model engineering | MLflow | `code/models/train_model.py` | `models/model.pkl`, `metrics.json` |
| 3. Deployment | Docker | `code/deployment/` | API and app containers |

Stages 1 and 2 are defined as DVC stages in `dvc.yaml`.
Stage 3 runs two separate containers via `docker-compose.yml`.
`code/pipeline.py` runs all three stages every 5 minutes.

## Repository structure

    code/
      datasets/      Stage 1: loading, cleaning, splitting
      models/        Stage 2: feature engineering, training, evaluation
      deployment/
        api/         FastAPI service + Dockerfile
        app/         Streamlit app + Dockerfile
        docker-compose.yml
      pipeline.py    orchestrator (runs everything every 5 minutes)
    data/
      raw/           source dataset (tracked by DVC)
      processed/     train/test split (produced by Stage 1)
    models/          trained model (produced by Stage 2)

## Setup

Requirements: Python 3.10+, Docker Desktop (running).

    git clone https://github.com/sunsanny/pmldl-assignment-1.git
    cd pmldl-assignment-1

    python -m venv venv
    venv\Scripts\activate          # Linux/macOS: source venv/bin/activate
    pip install -r requirements.txt

The raw dataset and the trained model are tracked by DVC and not stored in Git.
Download `atp_tennis.csv` from the Kaggle link above and put it into `data/raw/`.
The model is generated by the pipeline on the first run.

## Running the pipeline

Full automated pipeline (data → model → deployment, every 5 minutes):

    python code/pipeline.py

Or run the stages manually:

    dvc repro                     # Stages 1 and 2

    cd code/deployment
    docker compose up --build     # Stage 3

## Access

| Service | URL |
|---|---|
| Web application | http://localhost:8501 |
| API docs (Swagger) | http://localhost:8000/docs |
| MLflow UI | run `mlflow ui` in the repo root |

Enter the match parameters in the web app and press **Predict winner**.
The app sends a request to the API and displays the predicted winner
together with the model's confidence.

## Notes

- The API and the app run in separate Docker containers.
- The model file is mounted into the API container as a volume, so retraining
  does not require rebuilding the image.
- Betting odds (`Odd_1`, `Odd_2`) and the match score are dropped during
  cleaning — they would leak the outcome into the features.
